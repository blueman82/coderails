# Agentic Loop

Keep the main Codex session as orchestrator. Workers implement; the orchestrator owns one durable graph and is its only writer. `update_plan` is display only and never decides readiness, resume, or completion.

Set `SKILL_DIR` to the absolute directory containing this `SKILL.md`. The graph helper is `scripts/graph.py` beside this skill. It uses only the Python standard library. It calculates and records work but never starts agents, another provider, a nested session, or a scheduler.

## Start or resume

Read the SessionStart bootstrap text first. It reports either the active state path and inspection or the path for a new `progress.json`. Reuse that exact path after compaction or resume.

For a new loop, put the user's authorised outcome, verbatim, in a file and run `python3 "$SKILL_DIR/scripts/graph.py" start "$STATE" --session "$SESSION" --loop-id "<unique loop id>" --prompt-file "$PROMPT_FILE"` before any worker dispatch. It writes the schema-v3 state atomically (`in-progress`, revision 1, empty graph), treats a repeat of the same loop id as a no-op, re-arms a completed loop, and refuses with a `[reason_code=...]` when an unfinished loop owns the session: resume it instead. `$STATE` must end `<session>/progress.json`.

Register each work unit with `python3 "$SKILL_DIR/scripts/graph.py" add-unit "$STATE" --session "$SESSION" --loop-id "<same id>" --unit N [--depends-on M ...] [--join] [--manifest GLOB ...] [--worktree ABSOLUTE_PATH]`; set `--worktree` to the unit's checkout before graph-bound PR publication. It writes the work unit, its `U3[N]` node, the dependency edges and the `J12-all-units` input in one locked save. Never edit `progress.json` by hand for these steps.

Nodes other than `U3[N]` and `J12-all-units` use registered node IDs and their exact registered labels; every node carries `respawn: {"generation":0,"intent":null}`. An all-input join has an entry in `graph.joins` with `id` equal to the join key, `mode: "all"`, its registered input node IDs, and `released: false`. Downstream edges originate at that join. Active waves use `wave_id`. Unknown nodes, malformed state, cycles, inconsistent joins, or running nodes outside an active wave fail closed.

Keep the top-level `work_units` roster independent of `graph.nodes`: graph nodes record dispatch and control steps, while work units record the authorized deliverables. Completion requires every registered work unit to be `done` or `dropped` with a nonblank `dropped_reason`; never infer unit completion solely from graph-node status.

Create and freeze ungraded loop-local `evals.json` beside `progress.json` before build. The frozen suite must carry a nonblank `frozen_sha`, a positive verification level, at least one P0, valid eval modes and scripted command/negative-control fields, and null `result`/`grading`. Grade against actual outcomes at completion; do not fabricate a pre-build GO. It must carry this exact `session_id` and `loop_id`; those stable fields authorize dispatch across waves, so `begin-wave` does not invalidate the loop's eval authority. Keep its revision field as the revision at freeze or grading. The provider-local dispatch hook accepts valid frozen ungraded evidence before build or genuinely graded evidence, and blocks when graph ownership or loop evidence is missing or foreign.

For a graph with three or more work units, or any cross-unit dependency, apply `superpowers:brainstorming`'s design-quality discipline without its interactive human-approval gate. Write or reuse `spec.md` beside `progress.json`, then invoke `superpowers:writing-plans` to produce durable `plan.md` beside it, outside the code repository. `plan.md` is the static source of truth for scope and decomposition; `progress.json` is the dynamic record of position and outcomes. Derive node scope from the plan, and reread `spec.md` and `plan.md` on resume. Do not create these files for one or two self-contained units.

Before dispatching a writing node, invoke `superpowers:using-git-worktrees`. Use Coderails `prep` to perform the resulting worktree setup; it creates the worktree and, for a non-Git folder, the local `main` repository and initial commit it needs. Do not add a remote.

Before ending any turn that pauses an active loop, run `graph.py stop`: `python3 "$SKILL_DIR/scripts/graph.py" stop "$STATE" --session "$SESSION" --category <hard-stop|approval-gate|awaiting-input> --reason-code <code> --reason "<reason>"`. The Stop guard consumes that recorded row once (same vocabulary as Claude, from the shared `graph_vocab.py`); a `complete` row is never consumed and goes through `complete` / `verify-completion`. The final line is a rendering that hooks never read: without a row the guard blocks and traces `stop_row_missing`. Run `python3 "$SKILL_DIR/scripts/graph.py" inspect "$STATE"`. Inspection is the resume source of truth: loop and session identity, revision, active wave, running nodes, ready nodes, and hard-stop reason. Never reconstruct these from chat history.

## Run one wave

Every dispatch wave follows this order:

When composing each worker prompt, place the printed one-word `job_name` and `lane_code` after its machine ownership marker as a human-readable line with the stable node ID (for example, `Builder · A-1 [U3[1]]`). This display is descriptive only; use the stable node ID for task identity, authorization, and evidence.
1. Run `graph.py begin-wave "$STATE"`. This fully validates the graph, refuses an existing active wave, records the complete deterministic ready set as running, increments the revision, stores one single-use dispatch record per node in `graph.dispatches`, and prints the wave id, node list, `task_names` mapping and, per node, its `dispatch_id`, `prompt_prefix` and `prompt_sections`. Calling `begin-wave` is mandatory before `spawn_agent`; a state older than `state_minor` 2 must be converted first (`graph.py convert`, refused while a wave is open). `inspect` repeats the task-name mapping while a wave is active.
2. For a ready wave with two or more independent nodes, invoke `superpowers:dispatching-parallel-agents` for its parallel-dispatch guidance. It is advisory: `graph.py` still determines readiness and native `spawn_agent` remains the sole dispatcher.
3. With `sandbox_workers` on (the default), stop before a Codex `U3[N]` native spawn: `loop_dispatch_guard.py` denies it with `codex_native_worker_uncontained`. A separate OAuth worker can run through `packages/codex/scripts/codex_worker.py`, but its result cannot yet satisfy this graph's native evidence binder. Do not record it as `done`. The owner may explicitly set `sandbox_workers: false` to use the inherited parent sandbox. For nodes that can use native dispatch, call `spawn_agent` exactly once for each printed node. Use the provider-native `task_name` from the printed mapping when supported. The record's role is asserted: a guarded read-only scout node (preflight-scout, design-scout, disposition-scout, source-auditor, deploy-safety-reviewer) must be spawned with `agent_type` equal to that role; any other node accepts its own role or an unnamed native role, and never another named role (`role_mismatch`). If the tool has no role parameter, omit it for unguarded nodes rather than fabricating one. Its message must begin with the printed `prompt_prefix` (the `CODERAILS_GRAPH_DISPATCH=` envelope) on a line by itself, then the printed `prompt_sections` verbatim; in a session with a graph every `spawn_agent` is checked this way, whatever its `task_name`. The canonical task name encodes both the loop id and node id as lowercase UTF-8 hex, separated by `_`; retries and stale respawns append `_aN` (N is failed retries plus respawn generation plus one). This makes the native identity unique across loops as well as attempts, while remaining reversible. Read `../../agents/loop-worker.toml` relative to this skill and include its `developer_instructions` text explicitly after the pasted sections, followed by the task brief and current user restrictions. Explicitly require scoped implementation, test-first for testable changes, verification with actual command results, self-review, and an honest report; never assume a native label loads these instructions. User restrictions on commits, remote writes, or test scope override the template. Give each worker a self-contained prompt containing its node id, exact scope, allowed paths, worktree, exclusions, checks, required artifact, and concise evidence report. For testable code, require `superpowers:test-driven-development`; require `superpowers:subagent-driven-development` for worker construction and `superpowers:verification-before-completion` before its report. Do not use another provider or start a nested Codex session.
4. Use the exposed native wait tool (`wait_agent` in the collaboration surface) until every node in the active wave has a terminal report. A wakeup or mailbox notification alone is not a terminal result; `record-wave` resolves each task marker through either older `CollabAgentToolCall` spawn evidence or the native `spawn_agent` function call joined to its one `SubAgentActivity`, then child `source.subagent.thread_spawn` metadata and successful `task_complete`. Only loop-scoped task names (`task_names` from `begin-wave`) are accepted; a node-only pre-loop-scoped name is refused with `legacy_task_identity_refused`; a done node cannot be reopened, so such a loop is restarted under a fresh `--loop-id` (completed legacy loops also fail `verify-completion`). A quiet worker is not proof of failure: inspect its artifact, then use the exposed native message/follow-up tool for one focused correction if needed (`send_message` for a running worker, or `followup_task` to resume an idle worker on the collaboration surface).
5. Verify each report against the actual diff, test output, PR state, or other current artifact. A worker summary alone is not evidence. If a report or artifact is incomplete but correctable within the worker's scope, use one focused `send_message` or `followup_task`, then check the new report and artifact before recording `done`; if the worker is unavailable or the correction fails, use the graph's retry path. A worker that must stop for a human returns one typed status (`NEEDS_DECISION`, `OUTSIDE_SCOPE` or `IRREVERSIBLE_ACTION`, schema in `scripts/worker_status.py`); only the orchestrator asks the human, using `to_decision_request()`. `graph.py record-wave` validates the status itself (a malformed one rejects the whole report atomically, `worker_status_<code>`), records it in `worker_statuses`, counts it as a failed attempt, extending the terminal retry limit behind the pending decision only below the schema cap, and writes one typed stop row (`needs_human_input` for `NEEDS_DECISION`, `needs_approval` otherwise) that the Stop guard releases once; afterwards log the answer with `graph.py record-decision ... --worker-status-seq N [--human-answer]` (`--chosen` must be one of a `NEEDS_DECISION` status's options; `OUTSIDE_SCOPE` and `IRREVERSIBLE_ACTION` need `--human-answer`, passed only after the human replied). A worker's `done` result must also carry `final_report {claims: [{text, label, source?}], did_not_verify: [{item, tag, reason}]}` (a `verified` claim cites its source), else the report is rejected (`final_report_invalid`); it is stored in `final_reports[node]`.
6. Build one result object containing exactly every active-wave node and no other key. Each result is `{"outcome":"done|skipped|failed","evidence":"observed evidence"}`. Record it with:

```bash
python3 "$SKILL_DIR/scripts/graph.py" record-wave "$STATE" \
  '{"wave_id":"wave-N","results":{"U3[1]":{"outcome":"done","evidence":"check passed","final_report":{"claims":[{"text":"check passed","label":"verified","source":"test output"}],"did_not_verify":[]}}}}'
```

The envelope names a single-use dispatch record (`dispatch_replayed` on a second use) and the task name stays the evidence identity: it must equal the record's, and the evidence binder still keys on it (`graph_transcript`'s `CollabAgentToolCall` first-line reader is a historical-transcript path only). Native task paths, child/thread IDs, and any actual requested role are bound to provider transcript evidence. A supplied native role must match both child role fields; role-less dispatch is accepted only for the recognized `collaboration` function-call/activity shape with an explicit null nested spawn role; the top-level role may be absent or null, and any populated top-level path must agree. Parent/session, depth, unique dispatch, terminal completion for completed attempts, cursor, and reuse checks remain mandatory. A checked stale result verifies its unique native spawn and child ownership without inventing a successful terminal; subsequent completion rechecks every abandoned attempt from native transcripts. `loop_dispatch_guard.py` routes every spawn of a graph-bound session through `graph.py authorize-dispatch --dispatch-id --message-file --agent-type --task-name --tool-use-id` (state, session, active wave, record, sections, role, eval authorization) before dispatch; a spawn without a valid envelope is denied with a `dispatch_*` or `role_mismatch` row in `recovery-trace.jsonl`. When the native transcript stores the message as encrypted content, the binder requires the consumed hook authorization to name that native call id and rechecks the stored contract; an absent call id, an off-mode receipt, or an unconsumed historical spawn remains invalid. `add-unit` takes `--model-role`, `--write-scope`, `--lesson` and `--scope`, carried in the contract (write scope defaults to the manifest). Limit: Codex role containment (no shell, per-role MCP) is not part of this check; it asserts `agent_type` only.

If every worker in the active wave has been silent past a lease, run `graph.py recover-wave "$STATE" --session "$SESSION" [--lease-seconds N] [--report-only]`. It reports each node as `dispatch` (never spawned: spawn it now, nothing is recorded), `record` (finished or launch refused: record it), `waiting` or `stalled`, plus one stable `reason_code`. Only when all nodes are `stalled` does it, in one locked save, record them `stale` and request the respawn, so no attempt is counted without a stored worker reference. It refuses (`recovery_budget_exhausted`) once a node's respawns reach `retry.max`; a human then decides. Each outcome appends a non-authoritative row to `recovery-trace.jsonl` beside the state (see `docs/recover-wave-runbook.md`). For plain-language status run `graph.py summarize "$STATE"`; to list graph states and readable names for every node run `graph.py collection <state-root>`. An optional `collection.json` explicitly links graphs: `{"schema_version":1,"graphs":[{"key":"build","path":"build/progress.json","loop_id":"build-loop","links":["verify"]},{"key":"verify","path":"verify/progress.json","loop_id":"verify-loop","links":[]}]}`. Paths and loop IDs must match discovered schema-v3 states; links name keys, and unknown or ambiguous targets fail closed. Without the index, graphs are listed as disconnected. The command only reads graph states and returns graph links plus `unresolved_targets` (empty for a valid index). Malformed states fail the collection command. The Stop hook runs this recovery itself (at most once per 900s lease per graph state, within a 4s budget) when a blocked Stop finds a silent wave; it can respawn a worker that is alive but silent, so a duplicate is possible (bounded by `retry.max`). A timed-out attempt reports its outcome as unknown.

The collection command adds `key` and `links` to each graph record; an unlinked record has `"links": []`. Each node keeps its stable `id` and reports its one-word `name`, optional `lane_code`, and current `status` (for example: `{"id":"U3[15]","name":"Builder","lane_code":"C-3","status":"pending"}`). A missing or malformed target makes the command fail with a `graph:` error.

If `record-wave` refuses a finished single-node Codex spawn with `dispatch_missing_envelope`, inspect the native call and run `graph.py reject-invalid-dispatch "$STATE" --session "$SESSION" --node "$NODE" --wave-id "$WAVE" --report-only` first. Omit `--report-only` only after verifying that the next native dispatch can carry observable plaintext and the installed reader has passed the staged rollout in `docs/RUNBOOK.md`; set `CODERAILS_A6_EVIDENCE_WRITE=on` for the applying command. The command rechecks the exact completed spawn, missing plaintext envelope, unconsumed issued record, task identity and active wave. It records a **failed** attempt with a transcript reference, leaving the node pending only while retries remain. Dispatch the next wave with the printed plaintext envelope and successful `authorize-dispatch`; never treat the invalid worker's output as accepted work. Other dispatch refusals and multi-node waves remain blocked for diagnosis.

Partial, extra, malformed, wrong-wave, stale, failed, duplicate, foreign-session, or reused worker evidence is rejected without changing state. `record-wave` atomically adds compact transcript references to the existing node evidence array; workers never write graph state. A failed node increments its attempts and preserves a separate reference for that attempt. If a `spawn_agent` call was refused (for example "agent thread limit reached"), re-issue it with the same printed `task_name` until it succeeds; if it keeps being refused, report that node as `failed`, and `record-wave` binds the latest refused call (a call with an error output and no `SubAgentActivity`) as that attempt's reference. A refused call never satisfies `done`, `skipped`, or `stale`. A later `followup_task` turn on a recorded child does not invalidate its earlier recorded completion, but the child's latest turn must have completed successfully. It returns to pending while attempts remain; exhaustion becomes a durable hard-stop. Successful all-input joins release deterministically after every input succeeds. Repeat from `inspect`, then `begin-wave`.

**Scout spawn refusal fails closed.** If the design scout (or any independent reviewer) cannot be spawned (`agent thread limit reached` or any other capacity refusal), do not silently downgrade to the orchestrator's or a worker's own read. Retry the spawn with the same `task_name`; if it keeps being refused, record the node `failed` through `graph.py record-wave`, which binds the refused call as that attempt's reference (a refused call never satisfies `done`, and `record-wave` rejects it as success on Codex), then halt. A `not_found` on a `task_name` carried over from a previous session or resumed loop is not a capacity refusal: retry with a FRESH `task_name`, never the same one. Without an independent scout the loop HALTS for the human: do not continue past the refusal. A `non_independent` fallback requires explicit human approval. Only after the human approves, record `S2.5` as `skipped` with evidence beginning `non_independent: human approved` and run `graph.py record-decision` with that phase and decision text. That `skipped` record is the only exit that lets `J2` release without an independent scout; a `non_independent` read never counts as an independent review or as `done`. Hooks cannot spawn agents and no gate reads `non_independent`, so this is an orchestrator rule, not a hook-enforced one.

Before each `graph.py record-decision` call, read the current `loop_id` and `revision` from `progress.json`.
Pass them as `--loop-id` and `--revision`. The CLI refuses a stale caller.

**What consumes the thread limit.** Every spawned agent thread, including completed and idle ones, counts until it is retired. Before a scout spawn, retire completed threads with the provider's close tool where one exists (Codex: `close_agent`); otherwise nothing frees the slot, so record the limit in the refusal and halt rather than assume a thread was freed.

After independently verifying a deliverable and recording its wave, decide its registered work unit through `python3 "$SKILL_DIR/scripts/graph.py" record-unit "$STATE" --session "$SESSION" --unit "<id>" --status done --evidence "<observed check>"`. If the authorized deliverable is withdrawn, use `--status dropped --reason "<reason>"`. The command requires a pending unit and no active wave and records the decision atomically. The graph revision remains unchanged so stored wave evidence stays valid. A completed graph node never changes a work unit by itself. Grade final evals against the current graph revision.

Respect any user concurrency limit; otherwise use at most three workers at once. If a ready wave is larger, do not dispatch an unrecorded subset: define a graph whose wave width respects the limit before starting it.

## Review and release

Keep review provider-local. Use fresh Codex reviewer workers and the Codex workflow skills for review evidence, eval evidence, push, and merge. Review and release may be graph nodes, but never cross-provider joins. Treat every worker result as a claim until checked.

For a confirmed failure, make at most five distinct diagnosed repairs. When the cause is not obvious, invoke `superpowers:systematic-debugging` before another repair. Repeating the same action is not a new attempt. Stop on exhausted verification, a disproved premise, a material choice outside the authorised scope, or an unauthorised irreversible action. Record the reason in graph evidence and `hard_stop`. After a merged work-unit PR, use `superpowers:finishing-a-development-branch` for its worktree cleanup.

## Complete

Before completion, run `graph.py flush-decisions "$STATE" --session "$SESSION"`; preserve and report any
degraded Muninn sync, and stop on an invalid decision chain. Then update and regrade `evals.json`
against the graph's exact current revision and write beside the state:

- graded `evals.json` for the current session, loop, and revision;
- non-empty `proof.json` for the same session and loop, with every proof carrying a nonblank executable `cmd` and `status: "pass"`; or a saved no-proof reason when there is no executable surface;
- `retro.json` for the same session and loop, schema version 1 or newer, with `status: "complete"`.

For a loop with no executable surface, record the reason in `decisions_absorbed`. Leave `proof.json` absent. Get the current revision from `inspect`. Then run:

```bash
python3 "$SKILL_DIR/scripts/graph.py" record-proof-disposition "$STATE" \
  --session "$SESSION" --loop-id "$LOOP" --revision "$REVISION" \
  --disposition none --reason "no executable surface"
```

The command saves `none: no executable surface`. It refuses a foreign owner, a stale revision, an active wave, an existing proof file, or a repeated decision.

Prepare standing orders from the retro with code, never by editing Markdown. With `D` the repo-key dir (the grandparent of `$STATE`), `LOOP` the separate logical `loop_id` from owned progress, and `O="python3 $SKILL_DIR/../../scripts/lib/orders.py --dir $D --session $SESSION"`: run `$O record --failure-mode "<mode>" --lesson "<imperative lesson>" --loop "$LOOP" --quote "<verbatim words of the owner's own prompt, 12-300 chars>"` for each failure mode (add `--scope agnostic` for a lesson that applies to any repo). The native `complete` command runs `prepare` after final progress updates, including when none were recorded. Preparation binds the eligible owned source and records `orders_prepared`, with no recurrence or aging effect. Exit 3 prints a `reason_code`: report it and never write a Markdown fallback. `memory.backend: off` is the explicit opt-out. The current Muninn installation uses a newer API, so live lesson activation remains pending (see `docs/RUNBOOK.md`, "Standing order stored without a cite").

Flush and reload pending progress-source updates before final preparation. Changed sources are refused by default.
For a legitimate incomplete-source retry, use `$O prepare --loop "$LOOP" --refresh-from-sha256 <CURRENT evidence_sha256>`
with the current preparation's returned canonical hash. Immutable ownership must match, revision cannot roll back,
and that session+loop must have no applied tick or recurrence. Staged records are preserved with no effects. A saved
replacement whose receipt failed needs ordinary unchanged `prepare` to repair it. Never refresh completed inputs.

Apply `superpowers:verification-before-completion` to the orchestrator's completion claim. Then run:

```bash
PROOF="${STATE%/*}/proof.json"
python3 "$SKILL_DIR/scripts/graph.py" complete "$STATE" \
  --session "$SESSION" --evals "$EVALS" --proof "$PROOF" --retro "$RETRO" \
  --transcript "$TRANSCRIPT_PATH"
```

Keep this sibling `proof.json` path when the saved no-proof disposition leaves the file absent.

That command runs `prepare` before the graph lock, checks the prepared source under the graph lock, saves completion,
then runs `$O tick --loop "$LOOP"` and `$O render --loop "$LOOP"` after it releases the lock. Apply validates the
separately bound directory/session/logical-loop/source and the actual provider completion revision. New completed
recurrences reset counters; unmatched orders age once and become tombstones at K=5, never deletions. A failed native
completion save ages nothing. `orders_ticked` follows the ledger save; a failed postcompletion apply or observation
means `pending_teardown: true`. Repeat the same native `complete` command to resume the bound tick and render before
claiming teardown finished. `verify-completion` and the Stop guard refuse pending teardown.
An old complete loop without D4 receipts needs explicit reviewed legacy admission as documented in the orders
decision and runbook. Admission checks the exact file hash, then permits completion bookkeeping while binding the
graph source. It does not age orders; new loops cannot use it.

When `proof.json` exists, run each proof command through `functions.exec` using this canonical nested-result output; replace the placeholder with the proof's exact command so transcript matching remains exact:

```javascript
const result = await tools.exec_command({cmd: "<exact proof command>"});
text(JSON.stringify({loop_id: "<current loop id>", exit_code: result.exit_code, output: result.output}));
```

Completion refuses an active wave, pending/running/hard-stop nodes, a graph hard-stop, unreleased joins, missing or invalid native worker transcript references, wrong-loop evidence, stale eval revision, missing or ungraded evals, missing proof without a saved no-proof disposition, or missing retro. It rechecks every stored worker reference against the owning parent and child transcripts. When `proof.json` exists, it mines this session's Codex JSONL rollout and requires the last exact trimmed execution of every proof command in the current loop to carry a nested integer `exit_code` of zero and, for canonical results, the current `loop_id`; commands explicitly recorded under an earlier loop's turn context cannot replay. The outer `functions.exec` text `Script completed` alone is never proof of the inner command's success. This is local redirect-and-audit evidence, not a privilege boundary. Success atomically marks the loop complete and increments its revision. The provider-local Stop hook recomputes the same observed proof result before allowing a completed loop to end. A hard-stop, approval-gate or awaiting-input pause ends only via a recorded `graph.py stop` row; the final line is a rendering that is never read.
