Before a substantive step or claim, list your assumptions. Mark each one `verified` or `inferred`.

- Use `verified` for what a tool result, file read, or user statement shows in this session.
- Use `inferred` for what comes from a pattern, training, memory, or context.

**Why**. Unmarked inference is the leading cause of errors. Confident wording can make a guess look like a fact. On 2026-05-01 the user identified this problem in the recursive critique and called for a rule to show inference.

**When to apply**. Use this rule for tasks with multiple steps. Apply it to claims about paths, functions, behavior, or external conditions if you have no direct basis from this session. Give the list before you do the work. Keep it easy to find.
